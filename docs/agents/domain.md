# Domain docs

Use a single-context layout:

- `GLOSSARY.md` at the repository root.
- Architecture decision records under `docs/adr/`.

Before exploring an area, read the glossary and relevant ADRs
if they exist. Proceed silently when they are absent; create
them when terminology or decisions are actually resolved.

Use the glossary’s vocabulary in issues, proposals, code, and tests.
Prefer the book’s terminology when defining new compiler concepts.
Surface any conflict with an existing ADR explicitly.
